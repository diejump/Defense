# 作者原实现接入记录

日期：2026-11-11。

## 1. 当前实现

RIGBD、LoSplit、DShield、MAD使用固定版本作者源码和原生模型训练函数。作者入口中取得污染图后的参考训练、防御训练、原评估按源码段顺序复用；公共数据、固定样本、独立进程和保存逻辑单独编写。详细对应关系见[代码结构与实验协议](代码结构与实验协议.md)。

`upstream`的244个源码和配置文件均通过对应提交的Git blob检查。已去掉旧`src/rigbd.py`、`src/losplit.py`、`src/dshield.py`中的自写恢复及修正分支。独立作者进程避免各仓库的`models`、`utils`同名模块串用。

MAD保留作者两个固定辅助模型、完整联合规则、五个内部种子和对应五个最终模型。按用户确认，两个辅助模型继续使用全部原节点标签。结果、CSV和检查点均保存这项条件；不再用伪标签替换。

Prune直接调用LoSplit的`help_funcs.prune_unrelated_edge`，保留训练前剪边、测试触发图再次剪边及原模型fit。DPGBA选择LoSplit对应子目录的模型。RS、ABL从比较列表及本项目自写模块移除；作者模型工厂仍需导入的原ABL文件保留。

## 2. RIGBD核查

保留原参考训练、同骨架评分模型、发送端连接数恢复、原KL累计、已知目标类别、`find_index`切片及400轮原恢复。参数只把原常量K、丢边率转为可配置值，默认仍为20、0.5。原打印的目标类标签计数不是实际附着检测TP，结果不把它伪装成真实检测率。

未找到作者按“数据集/攻击”公开的最佳K、丢边率表。原默认与LoSplit公开候选网格见[RIGBD参数依据](RIGBD_参数依据_20261111.md)。公开网格可以作为后续调参范围，不能填成作者已确认最优配置。LoSplit的`split_lr`、`split_epoch`、`gamma`是它自己的参数，不是RIGBD的两个参数。

## 3. 已实测的作者代码问题

### LoSplit的GPU转换

`upstream/LoSplit/models/LoSplit.py::split_node`在第127行执行`labels_np = np.array(labels_list)`。当标签在GPU时触发`TypeError: can't convert cuda:0 device type tensor to numpy`；后面还存在`np.unique(labels)`等同类调用。Cora/UGBA/GCN已实际重现，该失败记录保留在GPU核验目录。

同一固定样本改用CPU，GCN、GAT、GraphSAGE三个原流程均训练成功，重载指标一致。当前运行说明使用CPU执行LoSplit。GPU其他方法和CPU LoSplit的耗时不用于速度比较；若要公平比较时间，先统一设备。

### LoSplit的DPGBA恢复接口

DPGBA分支的GAT、GraphSage原`forward`返回一个Tensor，但原`finetune2`用`output, x = self.forward(...)`接收。用真实Cora输入进行一轮接口检查时，两种骨架均在原恢复函数内报`ValueError: too many values to unpack (expected 2)`。同分支GCN的普通fit、重载和finetune2接口通过。

MAD的DPGBA分支三骨架普通fit和保存重载接口通过。本项仅检查原模型调用，复用已有Cora输入，不是DPGBA方法效果实验，不报告该攻击下的CA或ASR。记录见`outputs/author_source_20261111/dpgba_model_contracts`。目前DPGBA的LoSplit GAT、GraphSAGE属于原实现阻塞路径；按本次保持源实现的要求，保留原错误。

## 4. 本轮Cora核验

同时核查了公共无防御训练：原项目训练循环没有执行作者GAT在fit中的额外初始化，模型选择也有差异。现在无防御与ABP均直接调用RIGBD原模型fit，并删除自写训练器。在同一Cora/UGBA样本、种子和公共分类参数下，GAT无防御ASR由旧公共循环的5.78%变为原fit的100.00%。这组差异支持统一训练接口；本轮未单独拆分初始化和模型选择各自的贡献。

固定既有Cora/UGBA/seed10样本，训练附着预算27，三个骨架。GPU完成无防御、ABP、RIGBD、DShield、MAD、Prune共18项；CPU完成LoSplit共3项。无防御、ABP使用最后重跑的原fit结果；旧公共循环结果保留在原目录，不再列入当前比较表。GPU LoSplit的失败记录另行保留，不计入成功项。检查点复核结果详见最终核验报告。

完整结果及每种方法的指标条件见[Cora原作者流程核验](Cora原作者流程核验_20261111.md)。这些结果验证接入和重载；本轮并行运行过不同核验任务，日志耗时保留作运行事实，论文时间比较需要同设备、同重复数重新测量。

另外，普通Cora正常图入口完成5轮训练和单图评估，仅用于检查公共入口，不列入方法效果表。`uv lock --check --offline`通过，当前锁文件与新增作者依赖一致。
